0. 文档说明

本文档用于说明「Logo 风险检测工具」在 V1 版本需要实现的功能范围、业务流程和输出形式，不包含代码或假数据。

工具定位：对上传的 Logo 进行自动化风险分析，并生成可用于内部审核和对外沟通的 Safe-to-Use 报告。

LOONOOL 内部文档
仅用于产品与研发协作，不对外公开。

1. 产品背景

痛点与动机

  • 缺乏标准化的 Logo 风险评估流程（相似度、行业雷同、误解风险等）。
  • 缺少可复用、可归档、可对外展示的评估报告。
  • 现有审核高度依赖人工经验，难以做到一致、可追溯。

因此需要一套自动化、模块化的 Logo 风险检测工具，嵌入 LOONOOL 的图片审核工作流中，为品牌方、设计师和内部审核提供统一的判断依据。

2. 产品目标（Objectives）

  • 支持用户上传单个 Logo 进行检测。
  • 通过多维度分析输出结构化风险结论。
  • 给出统一的 Safe-to-Use 安全等级，便于快速决策。
  • 自动生成一份报告，可在线查看、可导出 PDF。
  • 支持报告多版本管理（v1 / v2 / v3…）。

3. 用户流程（User Flow）

3.1 高层流程

  • 用户在 Workspace 中创建任务（Task）。
  • 在任务中上传 Logo 图片。
  • 系统自动触发 Logo 风险检测。
  • 分析完成后生成一份报告并挂载到 Task 下。
  • 用户可查看报告详情、下载 PDF、再次发起检测生成新版本。

目标：从上传到拿到报告的路径尽量简单，减少额外交互。

工具定位：对上传的 Logo 进行自动化风险分析，并生成可用于内部审核和对外沟通的 Safe-to-Use 报告。

目标路径：上传 Logo → 自动检测四大风险模块 → 生成 Safe-to-Use 报告 → 在线查看 / 导出 PDF。

4. 核心检测模块（Feature Modules）

4.1 商标相似度检测

目标：识别 Logo 在视觉上是否与已有品牌外观存在相似风险，用于提示潜在外观冲突。

  • 关注：轮廓结构、图形/字母组合、配色倾向、整体风格。
  • 输出：相似度等级（低 / 中 / 高）、主要相似原因、非法律判断说明。

0. 文档说明

本文档用于说明「Logo 风险检测工具」在 V1 版本需要实现的功能范围、业务流程和输出形式，不包含代码或假数据。

本工具将作为 LOONOOL 图片审核系统中的一个独立能力模块，为品牌方、设计师和内部审核团队提供统一、可追溯的风险判断依据。

4.2 行业视觉冲突检测

目标：判断 Logo 是否与所在行业的主流视觉风格过度雷同，例如颜色、符号、构图模板等。

  • 输出：行业重叠度等级、冲突原因描述、行业视觉趋势说明。

4.5 综合安全等级（Safe-to-Use Grade）

综合上述四个模块结果，输出 A–E 的安全等级，并附一句话总结和主要原因说明。

5. 报告输出（Risk Report）

Logo 风险检测工具的核心成果是一份 Safe-to-Use 风险报告，挂载在 Task 下，支持多版本记录。

5.1 报告结构

  • 基础信息：Logo 缩略图、空间名、任务名、报告 ID、版本号、生成时间、审查方式。
  • 总体结论：安全等级、一句话总结、四大模块关键指标概览。
  • 详细分析：商标相似度、行业冲突、视觉风险、构图质量，各章节的结论与说明。
  • 综合建议：按优先级给出修改建议。
  • 风险声明与联系方式：用于规避法律风险并提供反馈渠道。

4.2 行业视觉冲突检测

目标：判断 Logo 是否与所在行业的主流视觉风格过度雷同，例如颜色、符号、构图模板等。

  • 输出：行业重叠度等级、冲突原因描述、行业视觉趋势说明。

6. 展现方式（Web & PDF）

6.1 Web 报告页

  • 独立报告详情页面，结构分块展示各章节。
  • 支持章节折叠/展开，顶部有返回 Task 的入口。

4.3 视觉误解风险检测

目标：识别该 Logo 是否可能被误解为警示符号、禁止符号或文化敏感图形。

  • 输出：风险等级、风险标签、误解场景说明。

6.2 PDF 导出

  • 基于 A4 排版，标题层级清晰。
  • 包含页眉（报告 ID + 版本号）与页脚（页码）。
  • 视觉风格正式，适合对外发送或内部汇报。

4.4 构图质量检测

目标：评估 Logo 本身的设计专业度和可用性（构图、留白、可读性、色彩对比等）。

  • 输出：构图质量等级、关键发现、优化建议。

7. 前端需求（FE Requirements）

  • 在 Task 详情页增加“报告列表”区域，展示所有版本报告。
  • 实现报告详情页，渲染各章节数据。
  • 提供“生成/重新检测”与“导出 PDF”按钮。
  • 适配移动端阅读体验（横向滚动最小化）。

4.5 综合安全等级（Safe-to-Use Grade）

综合上述四个模块结果，输出 A–E 的安全等级，并附上一句总结和主要原因说明。

8. 后端需求（BE Requirements）

  • 接收并存储上传的 Logo 文件。
  • 封装四大检测模块并统一输出分析结果。
  • 根据分析结果生成报告实体，并与 Task 建立关联。
  • 提供查询单个报告、查询 Task 下报告列表的接口。
  • 提供生成 PDF 的服务接口。

5. 报告输出（Risk Report）

Logo 风险检测工具的核心成果是一份 Safe-to-Use 风险报告，挂载在 Task 下，支持多版本记录。

5.1 报告结构

  • 基础信息：Logo 缩略图、空间名、任务名、报告 ID、版本号、生成时间、审查方式。
  • 总体结论：安全等级、一句话总结、四大模块关键指标概览。
  • 详细分析：商标相似度、行业冲突、视觉风险、构图质量等章节。
  • 综合建议：按优先级给出修改建议。
  • 风险声明与联系方式：用于规避法律风险并提供反馈渠道。

9. 数据与权限

9.1 数据层面

  • 每个报告记录需包括：任务 ID、版本号、生成时间、分析结果概要等。
  • 分析结果需结构化存储，方便后续前端渲染与版本对比。

9.2 权限与访问控制

  • 仅当前 Workspace 的成员可以查看对应报告。
  • 报告默认不公开，外部访问需要受控分享机制（如带 Token 的链接）。

6. 展现方式（Web & PDF）

6.1 Web 报告页

  • 独立报告详情页面，结构分块展示各章节。
  • 支持章节折叠/展开，顶部有返回 Task 的入口。

10. Out of Scope（不在本期范围）

以下能力本期不做，但可作为后续版本规划方向：

  • 批量 Logo 检测与比对。
  • 多 Logo 横向对比分析。
  • 对接真实商标注册数据库进行法律层面检索。
  • 自动生成替代设计方案的 AI 设计功能。
  • 可视化报告模板编辑与企业自定义样式。

6.2 PDF 导出

  • 基于 A4 排版，标题层级清晰。
  • 包含页眉（报告 ID + 版本号）与页脚（页码）。
  • 视觉风格正式，适合对外发送或内部汇报。

11. 非功能性需求（NFR）

  • 单次检测的响应时间在可接受范围内（数秒级）。
  • 报告页面加载流畅，无明显卡顿。
  • 系统出现错误时需给出清晰的错误提示与重试方式。

7. 前端需求（FE Requirements）

  • 在 Task 详情页增加“报告列表”区域，展示所有版本报告。
  • 实现报告详情页，渲染各章节数据。
  • 提供“生成 / 重新检测”与“导出 PDF”按钮。
  • 适配移动端阅读体验（横向滚动最小化）。

12. 验收标准（Acceptance Criteria）

  • 上传符合规格的 Logo 文件可以成功触发检测。
  • 四大检测模块均产生明确结果并展示在报告中。
  • 报告可在 Task 下正常创建、查询，版本区分清晰。
  • 用户可以成功导出 PDF，内容完整、排版正常。

8. 后端需求（BE Requirements）
